## 목표

단순 일기나 강의 자료 요약보다, **공책을 펼쳐 따라 적을 수 있는 설명**을 목표로 한다. 사용자는 본문을 훑는 독자와 하나씩 실습하는 독자 모두에게 도움이 되길 바란다.

TXT 원문에서는 오늘 배울 내용, Part별 개념/정의/표, API 흐름, 코드 해석, 필기 핵심, 퀴즈와 필기 우선순위를 연속해서 제공한다. 블로그는 그 문서의 전체 길이를 재현하지 않고, 독자가 이해할 핵심 원리·작은 예제·스스로 확인할 질문을 추려 구성한다.

## 4단계 목차

1. **개념** — 왜 필요한가, 한 문장 정의, 단어와 용어 차이, 실제 문제.
2. **실습** — 입력→처리→출력의 흐름, 짧고 독립적으로 실행 가능한 코드, 결과와 줄별 설명.
3. **확인** — 초보자가 실수하는 지점과 수정 방법, 반례·주의점, 스스로 풀 문제 2~3개.
4. **정리** — 공책에 적어둘 핵심 3~6줄, 요약 표/코드, 다음에 공부할 주제와 연결.

큰 장은 기본적으로 위 네 단계이고, 하위 제목은 1-1., 1-2., 2-1.처럼 작성한다. 단지 4개 장을 맞추려고 중요한 이유와 원리를 삭제하지 않는다.

## 쓰는 순서: 왜 → 무엇 → 어떻게 → 확인 → 응용

- **왜**: 독자가 부딪힐 수 있는 상황을 짧은 예로 먼저 제시한다.
- **무엇**: 한 문장 정의, 비슷한 개념과의 비교.
- **어떻게**: 순서도, 객체 참조 관계, 입출력 등 단계별 작동 원리를 설명한다.
- **코드**: Python/JSON 등 정확한 언어 태그, 복사 가능한 코드, 실행 사전 조건. 공개 API 키나 비공개 데이터를 넣지 않는다.
- **결과**: 실제 실행 후 확인한 출력은 '실행 결과', 실행하지 않은 코드는 '예상 출력', 비결정적 모델 응답은 '설명용 예시'로 구분한다.
- **해석**: 코드 각 줄이 무엇을 하고 *왜* 필요한지, 값이 어떻게 변하는지 설명한다.
- **확인과 응용**: 잘못된 코드의 오류 원인과 방지책을 비교하고 작은 실생활 적용으로 연결한다.

## 두 가지 읽기 깊이

- **훑어보기**: 중요한 정의, 표, 그림, 짧은 필기 핵심과 마지막 정리만으로도 구조가 보이게 한다.
- **집중 학습**: 자세한 문단 설명, 순서별 코드 해석, 실제·예상 출력, 작은 연습문제로 이해를 확장한다.
- 자주 헷갈리는 개념 끝에는 **공책에 적어둘 핵심**을 짧게 넣는다. 내용이 없는 예쁜 상자는 만들지 않는다.

## 시각화와 모바일

주제에 실제로 필요한 그림 1개를 우선 제안한다. 그래프의 수치·축·단위를 임의로 꾸미지 않는다. 인터랙티브 시각자료는 조작 없이도 이해할 수 있는 정적 설명과 대체 텍스트가 있어야 한다. 폴드·모바일 가독성과 키보드, reduced-motion을 함께 고려한다. 긴 표는 스크롤하고 코드/출력은 별도 블록으로 구분한다.

## 정확성 및 공개 경계

- 개인 경험, 실행 성공 여부, 정확한 출처, 실습 환경과 수업 페이지를 지어내지 않는다.
- 사적인 PDF, 유료 자료, 비공개 노트의 표현을 공개 글에 무단 복사하지 않는다.
- 한 편의 글에 모든 내용을 밀어 넣지 않고 적절한 학습 범위로 나눈다.
- 새 글은 기존 승인 원고의 깊이·번호·형식을 대조한다.
- **원고 작성 → 지피 검수 → 사용자 최종 승인 → 게시**. 예약 글은 항상 비공개 검토용이며 자동 게시하지 않는다.

## 필기용 작은 예시

### 1-1. 리스트가 필요한 이유

점수를 변수 세 개에 따로 저장하면 학생 수가 늘 때 관리가 어렵다. 리스트는 여러 값을 **순서대로 관리하는 가변 자료구조**다.

~~~python
scores = [85, 90, 78]
print(scores[0])
~~~

예상 출력:

~~~text
85
~~~

**왜 0일까?** 파이썬 리스트의 첫 요소는 인덱스 0이기 때문이다.

**공책에 적어둘 핵심:** 리스트 첫 인덱스는 0, 마지막 요소는 음수 인덱스 -1로 접근한다.
