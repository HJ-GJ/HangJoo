## 1. 이론: 내적(`a @ b`)은 왜 '그림자 곱하기'인가?

수업 교재(`numpy.html` Part 04)에서 가장 인상 깊었던 부분은 내적(Dot Product)을 단순 암기 공식이 아니라 **화살표의 그림자(정사영)**로 설명한 점이었습니다. 벡터 `[3, 2]`를 원점 `(0, 0)`에서 출발해 `(3, 2)`로 뻗어 나가는 화살표라고 생각하면, 위에서 손전등을 비췄을 때 바닥 화살표 위에 생기는 **그림자의 길이**와 **바닥 화살표의 길이**를 곱한 값이 바로 내적입니다.

:::formula
내적 계산 공식 | a @ b = a₁b₁ + a₂b₂ + ... + aₙbₙ | 같은 자리의 숫자끼리 곱한 뒤 모두 더해 숫자 딱 하나(스칼라)로 압축합니다.
방향과 내적의 부호 | 같은 방향: 양수(+) / 직각(90°): 0 / 반대 방향: 음수(-) | 두 벡터의 성향이 비슷할수록 내적 점수가 커지고, 전혀 무관하면 0이 됩니다.
행렬곱 크기 규칙 | (m × n) @ (n × p) = (m × p) | 앞 행렬의 열 개수(n)와 뒤 행렬의 행 개수(n)가 같아야만 곱할 수 있습니다.
:::

이 원리를 알면 **추천 시스템(영화 취향 매칭)**이 왜 내적을 쓰는지 바로 이해할 수 있습니다. 내 취향 벡터가 `[액션, 로맨스] = [4, 5]`일 때, 영화 A(`[5, 4]`)와 내적하면 $4 \times 5 + 5 \times 4 = 40$점이 나오지만, 성향이 정반대인 영화 B(`[5, 0]`)와 내적하면 $20$점에 그칩니다.

## 2. 비교: 원소별 곱셈(`A * B`) vs 행렬곱(`A @ B`)

NumPy를 처음 배울 때 가장 많이 헷갈리는 부분이 별표(`*`) 연산자와 골뱅이(`@`) 연산자의 차이입니다.

:::compare
### 원소별 곱셈 (`A * B`)
- 두 행렬의 모양(`shape`)이 완전히 같아야 함 (또는 브로드캐스팅 가능)
- 단순히 같은 위치(예: 0행 0열끼리)에 있는 숫자만 1:1로 곱함
- 행과 열의 조합이나 좌표 공간 변환은 일어나지 않음
---
### 행렬곱 (`A @ B` 또는 `np.dot(A, B)`)
- **내적의 표:** 결과 행렬의 `(i, j)` 칸은 **`A`의 `i`번째 행과 `B`의 `j`번째 열을 내적한 값**임
- 안쪽 숫자(`A`의 열 개수 == `B`의 행 개수)가 일치해야만 계산 가능
- **순서가 바뀌면 결과가 달라짐 (`A @ B ≠ B @ A`):** 가로 먼저 늘리고 회전하는 것과 회전 후 늘리는 것이 다른 것과 같음
:::

```python
# title: numpy_part2_dot_and_matmul.py — 영화 취향 내적 추천과 행렬곱(A @ B) 검증
# takeaway: 행렬곱 A @ B의 결과 모양은 바깥쪽 두 숫자인 (A의 행 수, B의 열 수)로 결정되며, A @ B 와 B @ A 는 결과가 다릅니다.
import numpy as np

# 1) 내적(a @ b)으로 내 영화 취향([액션=4, 로맨스=5])과 가장 비슷한 영화 찾기
my_taste = np.array([4, 5])
movies = np.array([
    [5, 4],  # 영화 0: 액션+로맨스 조화
    [5, 0],  # 영화 1: 순수 액션
    [0, 5],  # 영화 2: 순수 로맨스
])

# 핵심: (3, 2) 영화 행렬과 (2,) 내 취향 벡터를 @ 연산하면 3편의 추천 점수가 한 번에 계산됩니다.
scores = movies @ my_taste
print("영화별 추천 점수:", scores)  # [40, 20, 25] -> 영화 0번(40점) 추천!

# 2) 행렬곱 크기 규칙 (2x3) @ (3x2) -> (2x2) 및 순서 비가환성 확인
A = np.array([[1, 2], [3, 4]])
B = np.array([[5, 6], [7, 8]])
print("A @ B 결과:\n", A @ B)  # [[19, 22], [43, 50]]
print("B @ A 결과:\n", B @ A)  # [[23, 34], [31, 46]] (A @ B 와 다름!)
```

## 3. 실습: 점 옮기기(`p @ A`)와 GPU가 필요한 이유

교재의 마지막 장(`05 왜 필요할까?`)에서는 점 `p = [x, y]`에 $2 \times 2$ 변환 행렬 `A`를 곱해(`p @ A`) 점의 위치를 이동시키는 실험을 다뤘습니다.

- **첫째 줄 `[a, b]`:** 원래 `x`좌표 `(1, 0)`이 어디로 이동하는지 결정
- **둘째 줄 `[c, d]`:** 원래 `y`좌표 `(0, 1)`이 어디로 이동하는지 결정

게임 그래픽이나 딥러닝 이미지 처리에서는 점 하나가 아니라 **수백만 개의 점(`N × 2` 행렬)을 한꺼번에 회전·확대·투영**해야 합니다. 일꾼이 몇 명뿐인 CPU는 이를 순서대로 계산하지만, 작은 일꾼 수천 개가 모인 **GPU**는 수백만 줄의 행렬곱을 동시에 처리하기 때문에 AI 학습에 필수적입니다.

```python
# title: numpy_part2_transform.py — 2x2 변환 행렬로 여러 점 동시에 회전·확대하기
# takeaway: 점 4개를 담은 (4, 2) 행렬에 (2, 2) 변환 행렬을 한 번만 곱하면(points @ R), 반복문 없이 모든 꼭짓점이 동시에 회전합니다.
import numpy as np

# 정사각형의 네 꼭짓점 좌표 (4개의 점 x 2차원 좌표)
points = np.array([
    [0, 0],
    [2, 0],
    [2, 1],
    [0, 1]
])

# 1) 가로 2배 확대 행렬
scale_x2 = np.array([
    [2, 0],
    [0, 1]
])

# 2) 반시계 방향 90도 회전 행렬: (1,0)->(0,1), (0,1)->(-1,0)
rotate_90 = np.array([
    [0,  1],
    [-1, 0]
])

# 핵심: 반복문 없이 행렬곱 한 번으로 4개 꼭짓점 전체를 동시에 변환합니다.
stretched = points @ scale_x2
rotated = points @ rotate_90
print("가로 2배 확대 좌표:\n", stretched)
print("90도 회전 좌표    :\n", rotated)
```

## 4. 최종적으로 내가 알아낸 내용

:::finding
### NumPy Part 2 (교재 04~05) 학습으로 내가 직접 정리한 핵심 포인트
- **내적(`a @ b`)은 '유사도 측정기'이고 행렬곱(`A @ B`)은 '내적의 종합 성적표'임:** 학생 3명의 과목 점수표 `(3 × 3)`와 과목별 가중치 세트 2개 `(3 × 2)`를 행렬곱하면, 3명 × 2가지 방식의 총점 표 `(3 × 2)`가 단 한 번에 완성됩니다.
- **차원이 안 맞을 때(`ValueError: matmul`)는 항상 안쪽 숫자부터 확인할 것:** `(m, n) @ (n, p)`에서 가운데 맞닿는 두 숫자 `n`이 일치하는지`.shape`로 찍어보는 습관이 디버깅 시간을 가장 크게 줄여줍니다.
- **딥러닝의 선형 계층(`y = x @ W + b`)이 바로 행렬곱 + 브로드캐스팅의 결합임:** 입력 데이터 행렬 `x`에 가중치 행렬 `W`를 행렬곱(`@`)으로 변환한 뒤, 편향 `b`를 브로드캐스팅(`+`)으로 더해주는 구조가 신경망의 가장 기본 블록이라는 점이 명쾌하게 연결되었습니다.
:::
